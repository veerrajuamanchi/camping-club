# Canonical State Persistence Matrix

**Status:** Canonical planning contract for persistence and side effects. `*_status` and `*_state` projection columns are caches, not financial or lifecycle facts. Every consequential transition uses a trusted operation and append-only event/audit record.
**Related:** [Database Schema](DATABASE_SCHEMA.md), [API Contracts](API_CONTRACTS.md), [State Machines](STATE_MACHINES.md)

## Persistence invariants

1. Append-only facts include business transition events, all sent/received/refund payment events, finalized settlement inputs/outputs, ledger postings, rule acknowledgments, lottery draw results, and audit evidence.
2. Status columns are rebuildable projections. A projection update cannot independently authorize a state transition, create a receipt, discharge an obligation, or alter a finalized amount.
3. A trusted database transaction appends fact(s), updates projection(s), writes audit data, and inserts outbox intent atomically. External delivery occurs after commit and records its own outcome.
4. `sent` is not `received`; email accepted is not email delivered; club trip cancellation is not campsite cancellation; booking coverage is not cash receipt.
5. At any transition, persist the actor, source state/version, target state, reason where required, event key, and linked idempotency record. Scheduler decisions also store cutoff, basis, count, and counted record IDs/hash.
